# v0.1 MVP: capture and share

## Goal

A user can install MobileScan, photograph one sheet of paper inside the DIN frame, pick a
compression level and hand a single-page A4 PDF to any app via the OS share sheet.
No editing yet. Everything else in the spec is deferred, but the data model already
carries the frame geometry so that v0.2 does not need to restructure it.

## Scope

In:
- Project setup: TypeScript + Vite, Vitest, ESLint, `npm run build` producing `dist/`.
- PWA shell: `manifest.webmanifest` (name MobileScan, `lang: de`, `display: standalone`,
  `orientation: portrait`, app icon from `icons/app-icon.svg` rendered to 192/512 px PNG),
  a minimal service worker that precaches the app shell only.
- Start page with the single text button "Dokument scannen".
- Camera view: rear camera via `getUserMedia`, live preview, dashed DIN frame overlay, shutter button, back button.
- Capture: full-resolution still from the video track into an offscreen canvas. Frame geometry stored alongside.
- Captured view: shows the frame area only. Buttons [back] [share] [edit]. Edit is present but disabled (greyed) in v0.1.
- Share sheet: segmented compression control (3 levels), cancel, confirm.
- PDF generation: JPEG at the chosen quality, embedded on a fixed A4 page, scaled to fit, orientation follows the image.
- Web Share with a `File`. Success returns to the start page and discards all image data. Cancel keeps the captured view.
- Busy overlay while encoding and building the PDF.
- Deploy script `scripts/deploy.sh` reading `DEPLOY_HOST` and `DEPLOY_PATH` from a git-ignored `.env`.

Out: crop, rotate, brightness/contrast, camera error handling beyond a console log, install hints, animations.

## Behaviour

Start page
- "Dokument scannen" requests the camera and navigates to the camera view.

Camera view
- Constraints: `{ video: { facingMode: { ideal: "environment" }, width: { ideal: 4096 }, height: { ideal: 4096 } }, audio: false }`.
  The stream's actual size is read from the track settings and used for capture.
- The `<video>` is displayed with `object-fit: cover`. The overlay frame is drawn in viewport
  coordinates by mapping the frame from captured-image coordinates through the same cover transform,
  so what the user sees inside the dashes is exactly what the captured view shows.
- Shutter: draw the current video frame to a canvas of the track's native size. Stop the stream afterwards.
- Back: stop the stream, return to the start page.

Captured view
- Displays only the frame region of the captured image (canvas `drawImage` with source rect = frame).
- Back: discard the image, reopen the camera.
- Share: open the share sheet.

Share sheet
- Compression levels map to JPEG quality: small 0.5, medium 0.75, large 0.92. Default medium. Not persisted.
- Confirm: render frame region to a canvas, encode JPEG, build the PDF, call `navigator.share({ files: [pdf], title: "Scan" })`.
- If `navigator.canShare` rejects files, log and show the error state from v0.4; for v0.1 fall back to a download link of the PDF.
- Resolve: clear the canvas and all references, go to the start page. Reject with `AbortError`: close the sheet, stay on the captured view.

PDF
- Page: A4 portrait 595.28 x 841.89 pt; if the image is wider than tall, A4 landscape.
- Image scaled uniformly to fit inside the page, centred. Borders on one axis are accepted (decision 2026-09-22).
- File name: `scan-YYYYMMDD-HHMMSS.pdf`. Title metadata "MobileScan".
- Library: pdf-lib (pure JS, JPEG embedding, no fonts needed). jsPDF is the fallback if bundle size is an issue.

## Data model

```ts
interface Capture {
  image: HTMLCanvasElement | ImageBitmap;   // full captured image, never cropped
  frame: Frame;                             // in image pixel coordinates
}
interface Frame {
  cx: number; cy: number;                   // centre
  width: number; height: number;            // frame size along its own axes
  angle: number;                            // radians, 0 in v0.1
}
```

Initial frame: `width = 0.9 * image.width`, `height = width * sqrt2`, reduced proportionally
if `height > 0.9 * image.height`; centred; angle 0.

Held in memory only. Cleared on share success, on back from the captured view, and on page unload.

## Technical notes

- Camera needs a secure context: `vite` dev server with `--host` and a self-signed certificate
  (`@vitejs/plugin-basic-ssl`) so phones on the LAN can test.
- iOS Safari caps canvases at about 16.7 M pixels; downscale the capture if width*height exceeds 16 M.
- `ImageCapture.takePhoto()` is Android-only; not used, video-frame capture is sufficient for the MVP.
- The service worker must never cache blobs or canvases; it precaches only the built assets.
- Apache on uberspace: add `.htaccess` with correct MIME type for `.webmanifest` and `Service-Worker-Allowed`.

`shutter`, `arrow-left`, `share`, `edit` (disabled), `file-small`, `file-medium`, `file-large`, `close`, `check`, `spinner`, `app-icon`.

## Acceptance criteria

- Installable on Android Chrome and iOS Safari (add to home screen); launches standalone in portrait.
- Photograph an A4 sheet placed inside the dashes; the captured view shows the sheet with the same borders the dashes showed.
- Share to Files/Drive/Mail on both platforms; the PDF opens, is A4, and contains the frame region only.
- Three compression levels yield visibly different file sizes for the same capture.
- After sharing, the app is on the start page and DevTools memory shows no retained image.
- Cancelling the share sheet returns to the captured view with the image intact.
- Reloading the app offline shows the start page (shell cached), but no image.
- `npm test` covers: initial frame computation, PDF page orientation and fit maths, quality mapping.
