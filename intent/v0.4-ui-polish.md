# v0.4 UI polish

## Goal

Make the app feel finished: robust against permission and API failures, responsive,
accessible despite having no labels, and consistent in its icon language.

## Scope

In:
- Camera error state (permission denied, no camera, insecure context): icon-only screen with retry and back.
- Share unsupported: if `navigator.share` with files is unavailable, offer a download (`<a download>`) with the same confirm button.
- Busy states: PDF generation and rotation baking show the spinner overlay and block input.
- Transitions: 150 ms cross-fades between screens; the popover animates from the edit button.
- Accessibility: every icon button has an `aria-label` (German), focus rings, 44 px targets, `prefers-reduced-motion` respected.
- Safe areas: honour `env(safe-area-inset-*)`; the button bar never sits under the home indicator.
- Theme colour, splash background, maskable app icon variant.
- Final icon set: review the `icons/` SVGs at 24 px on device, adjust stroke weights, add the maskable icon.
- Lighthouse PWA audit passes; bundle size budget 250 kB gzipped including the PDF library.
- Optional, to decide during v0.4: an iOS "add to home screen" hint. Currently out (decision 2026-09-22).

Out: multi-page documents, OCR, perspective correction, settings.

## Behaviour

- Retry re-requests the camera. On iOS, a permanently denied permission cannot be re-prompted; retry then leads to the same state, which is accepted.
- Page hide (`visibilitychange` to hidden) while on the camera stops the stream; returning restarts it.
- `beforeunload` clears image references (defensive; the browser drops them anyway).

## Acceptance criteria

- Denying camera permission shows the error screen; granting after retry shows the camera.
- VoiceOver and TalkBack read a meaningful German label for every button.
- Lighthouse: PWA installable, accessibility score >= 95, performance >= 90 on a mid-range Android phone.
- Lower third of the camera view remains tappable on iPhones with a home indicator.
