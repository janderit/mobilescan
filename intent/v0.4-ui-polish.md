# v0.4 UI polish

## Goal

Make the app feel finished: robust against permission and API failures, robust against the
phone's own navigation (back button, backgrounding), responsive, accessible despite having no
labels, and consistent in its icon language.

## Status at the start of v0.4 (2026-09-22)

Already in place from v0.1 to v0.3, to be verified on device rather than built:

- Share fallback: `src/share.ts` downloads via `<a download>` when the browser cannot share files.
- Safe-area CSS variables and `viewport-fit=cover`.
- German `aria-label` on every icon button (via `src/ui.ts`), status role on the busy overlay,
  reduced-motion variant of the spinner.
- Busy overlay during PDF generation.
- Theme colour in manifest and HTML head.
- Bundle: about 186 kB gzipped JavaScript, mostly pdf-lib; within the 250 kB budget.

## Scope

In:
- Camera error state (permission denied, no camera, insecure context): icon-only screen with
  retry and back. Today a failed camera start only logs to the console and leaves the user on
  the start page.
- Error feedback for the other failure paths (share, rotation bake, tone bake), which are
  currently swallowed silently: the warning icon is shown briefly (about 2 s) over the current
  view, then the view stays as it was. No text.
- Busy states: PDF generation and rotation/tone baking show the spinner overlay and block
  input. Baking is synchronous, so the bake must be deferred until after the overlay has
  painted (two animation frames after the render), otherwise the spinner never appears.
- History integration: every screen change pushes a history entry; `popstate` acts as the
  on-screen back button of the current screen (captured -> retake, edit views -> discard
  pending edits, sheet/menu -> close). The hardware back button on Android and the swipe-back
  gesture on iOS therefore never leave the app while a scan is in progress. Leaving the start
  page via back exits as usual.
- Transitions: 150 ms cross-fades between screens; the popover animates from the edit button.
  Retake opens the camera directly instead of routing through the start page, so no
  intermediate fade shows. Under `prefers-reduced-motion` all transitions are instant.
- Shutter feedback: brief white flash over the camera view on capture; `navigator.vibrate`
  where available (Android). Both off under reduced motion.
- Accessibility: every icon button has an `aria-label` (German), visible focus rings on all
  controls, 44 px targets, `prefers-reduced-motion` respected.
- Safe areas: honour `env(safe-area-inset-*)`; the button bar never sits under the home
  indicator. Check every screen, including the share sheet and the edit views.
- Maskable app icon variant: padded, filled background, rendered by `scripts/render-icons.mjs`
  and listed in the manifest with `purpose: maskable`.
- Final icon set: review the `icons/` SVGs at 24 px on device, adjust stroke weights.
- Tests: jsdom tests for the app state machine covering the camera error path, the share
  fallback, and the history handling. The existing suite covers geometry, PDF and tone only.
- Audit: accessibility and performance scores via Lighthouse, installability via the Chrome
  DevTools Application panel; bundle size budget 250 kB gzipped including the PDF library.

Out: multi-page documents, OCR, perspective correction, settings, iOS splash images, iOS
"add to home screen" hint (decision 2026-09-22, confirmed at v0.4 start).

## Behaviour

- Retry re-requests the camera. On iOS, a permanently denied permission cannot be re-prompted;
  retry then leads to the same state, which is accepted.
- Page hide (`visibilitychange` to hidden) while on the camera stops the stream; returning
  restarts it. On iOS the stream dies in the background anyway; without the restart the view
  comes back frozen or black.
- `beforeunload` clears image references (defensive; the browser drops them anyway). No
  "are you sure" prompt: it is unreliable in standalone mode and the history integration
  covers the accidental-back case.
- Errors during share or baking leave the image and the current view untouched; only the
  brief warning indication is shown.

## Acceptance criteria

- Denying camera permission shows the error screen; granting after retry shows the camera.
- Hardware back on Android (installed app) from the captured view returns to the camera, not
  to the launcher; from an edit view it discards the pending edit.
- Backgrounding the app on the camera view and returning shows a live camera again.
- VoiceOver and TalkBack read a meaningful German label for every button.
- Lighthouse (Chrome DevTools, against https://mobilescan.app/app/): accessibility score
  >= 95, performance >= 90 on a mid-range Android phone. The Application panel reports the
  app as installable with a maskable icon and no manifest warnings.
- Lower third of the camera view remains tappable on iPhones with a home indicator.
- The busy spinner is visible while a full-resolution image is rotated or tone-adjusted.
