# v1.0.1 Install button on the start page

## Goal

The spec says the browser prompts to install the PWA on the first visit. In practice Chrome
shows a small infobar that is easy to miss, and Safari on iOS shows nothing at all; the user
has to know the share sheet route. v1.0.1 lets the start page notice that it runs in a browser
tab rather than installed and offer the install itself, in the way each browser allows.

## Scope

In:
- Detection: the app runs installed when `(display-mode: standalone)` matches (the manifest
  declares `display: standalone`) or, on iOS, `navigator.standalone` is true. Then nothing is
  offered. No browser tells a tab whether an install exists elsewhere on the device, so
  "not standalone" is the signal.
- Chrome on Android (and other Chromium browsers): `beforeinstallprompt` is kept (with
  `preventDefault`, so Chrome's own infobar stays away) and the install button calls its
  `prompt()`. The event serves once; after a dismissal the button goes until Chrome fires a
  new event, which it does on a later visit. `appinstalled` hides the button for good.
- iOS (Safari, and Chrome on iOS, which is WebKit without an install API): the button opens a
  help card over the start page with the intro "So installierst Du die App:" and the two steps of the share sheet route, each an icon with
  its caption: "Teilen" and "Zum Home-Bildschirm". Closing via the close button or the
  backdrop. iPadOS reports itself as a Mac with touch, so that counts as iOS too.
- Other browsers (desktop, Firefox for Android): no event, no help; the button does not appear.
- Placement: the install button shares the slot under the start button with the update
  button (icon: arrow into a tray, `aria-label` "App installieren"). Both can show at once.
- Session state only. Nothing is persisted; the help card is not a history entry (the start
  page keeps the back trap inactive).

Out:
- Detecting an existing install from a browser tab (`getInstalledRelatedApps` is Android-only
  and needs a related-app declaration; not worth it).
- A "do not show again" for the button: it disappears once the app is installed, and in the
  browser it is a small icon in an otherwise empty slot.

## Text exception

The help card's intro line and captions are the third visible text after "Dokument scannen" and the
compression captions: there is no install API on iOS, so the app cannot act, only explain,
and a share icon plus a plus icon alone do not explain the route.
