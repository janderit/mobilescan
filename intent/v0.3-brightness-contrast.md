# v0.3 Brightness and contrast

## Goal

The second edit entry becomes active. The user adjusts brightness or contrast with one
slider, sees the result immediately, and bakes it into the image on confirm.

## Scope

In:
- Brightness/contrast view with the frame region of the image, one slider, segmented [brightness|contrast], [back], [confirm].
- Live preview through CSS `filter: brightness() contrast()` on the displayed canvas (no pixel work while dragging).
- Confirm applies the same filter through the 2D canvas `filter` property (Chrome, Safari 16.4+) and replaces `capture.image`.
  Fallback: manual per-pixel loop with the same formula if `ctx.filter` is unsupported.
- Back discards the pending values.

Out: gamma, grayscale, black-and-white threshold, auto-levels.

## Behaviour

- Ranges: brightness 0.5 .. 1.5 (neutral 1.0), contrast 0.5 .. 2.0 (neutral 1.0). The slider is linear in the
  displayed range with a tick at neutral. Switching the segment swaps which value the slider shows.
- The view shows the frame region only, like the captured view, since the margins are not relevant here.
- Slider is a native `<input type="range">` styled icon-only; label via `aria-label` only.
- Confirm: draw `capture.image` onto a new canvas with `ctx.filter = "brightness(b) contrast(c)"`, replace the image.
  The frame is unchanged. Both values then reset to neutral for the next visit; edits accumulate in the image.
- Baking affects the whole captured image including margins so that later cropping stays consistent.

## Icons used

`brightness`, `contrast`, `arrow-left`, `check`.

## Acceptance criteria

- Dragging the slider updates the preview within one frame on a mid-range Android phone (no canvas redraw per event).
- Confirm output matches the preview visually; unit test verifies the fallback loop against the filter formula on a small image.
- Neutral values leave the image bit-identical.
- Back leaves the image unchanged.
