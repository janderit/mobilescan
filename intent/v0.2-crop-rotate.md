# v0.2 Crop and rotate

## Goal

The edit submenu becomes active with its first entry. The user can move and resize the
frame on the full captured image, correct skew by a few degrees, turn the image in
90-degree steps, and confirm. Cropping only changes the stored frame; rotation is baked
into the image on confirm with white fill.

## Scope

In:
- Edit popover on the captured view with two icons: crop/rotate (active), brightness/contrast (disabled until v0.3).
- Crop/rotate view showing the full captured image at 100 % with the frame at its stored geometry.
- Button row [back] [crop|rotate] [rotate 90 right] [confirm].
- Crop mode: drag the frame body, the four edges, the four corners. All in frame-local coordinates.
- Rotate mode: drag around the frame boundary to rotate the frame about its centre, clamped to ±15° relative to the last baked orientation.
- 90-degree button: adds +90° to the frame angle and swaps the frame's width and height. Works in both modes.
- Confirm: if the frame angle is not 0, rotate the image about the frame centre by -angle, fill exposed areas white, set angle to 0. Then return to the captured view.
- Back: discard the pending frame and pending rotation, return to the captured view.

Out: perspective correction, auto edge detection, aspect-locked cropping, pinch zoom.

## Behaviour

Display
- The view fits the full image into the available area (letterboxed). A single `viewTransform`
  (scale + offset) maps image pixels to CSS pixels. All hit testing converts touch points to image coordinates first.
- The image stays still on screen at all times (spec: "the image stays constant, but the frame is moved").
  The frame is drawn rotated by `angle` about its centre, its handles rotate with it. White fill is not
  previewed; it appears after confirm. Keeping the image still makes it obvious which part of the
  photo the frame covers and matches the spec's note that cropping must work on a rotated frame.

Crop mode
- Handles: 4 corners and 4 edge midpoints, 44 px touch targets in CSS pixels.
- A drag on a handle is converted into frame-local coordinates: `local = R(-angle) * (p - centre)`.
  Edges move along the frame's own axes, so cropping is independent of the frame's rotation (spec requirement).
- Dragging the frame body translates the centre.
- Constraints: minimum frame size 10 % of the image width; the frame may not leave the captured image.
  If the constraint would be violated, the drag is clamped, not rejected.
- Aspect is free; no DIN lock.

Rotate mode
- Touch start anywhere in the view records the angle from the frame centre to the touch point.
  Touch move applies the angle delta to the frame angle, clamped to `[base - 15°, base + 15°]` where `base` is the
  nearest multiple of 90°.
- Snap to `base` within ±0.5°.

90-degree button
- `angle += 90°`, then `swap(frame.width, frame.height)`. The centre stays.
- Fine skew is preserved across taps because it is relative to `base`.

Confirm
- If `angle == 0`: store the frame, return.
- Else: create a new canvas of the rotated image's bounding size, fill white, draw the image rotated by
  `-angle` about the frame centre, replace `capture.image`, transform the frame centre into the new canvas, set `angle = 0`.
- For exact multiples of 90° the bounding box is the swapped image size and no white appears.
- Memory: the previous canvas is released immediately; only one full-size copy exists at a time plus the working copy during the draw.

## Data model changes

`Frame.angle` becomes live. Add to the crop/rotate view a `pending: Frame` copy; `capture.frame` is only replaced on confirm.

## Icons used

`crop`, `rotate`, `rotate-90-right`, `brightness` (disabled), `arrow-left`, `check`, `edit`.

## Acceptance criteria

- Cropping never changes `capture.image` pixel data (unit test compares canvas hash before/after).
- Dragging the right edge after a 90° tap moves the edge that is on screen right, and the stored frame width along its own axis changes accordingly.
- A 5° skewed capture can be straightened; the shared PDF shows a straight page with white wedges at the crop border only if the crop reaches into the fill.
- Four 90° taps followed by confirm reproduce the original image bit-for-bit for the frame region (allowing for the intermediate copy being the same pixels).
- Back discards all changes; the captured view is unchanged.
- Frame-local edge/corner maths and rotation baking are covered by Vitest with rotated fixtures.
- Handles remain usable with a thumb on a 360 px wide viewport.
