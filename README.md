# MobileScan

MobileScan is a progressive web app that allows users to scan paper documents on mobile devices (Android + iPhone) and save them as PDFs with minimal image processing.

- Repository: https://github.com/janderit/mobilescan
- App: https://mobilescan.app/app/

## Raison d'etre

MobileScan is a small utility app that does not send data anywhere except for the save / share-to location selected by the user. In particular, all processing happens locally in the device's browser.
Its sole purpose is to scan a paper document, allow for simple cropping as well as brightness + contrast correction, and embed the resulting image in a PDF file with selectable compression level.
The PDF is then saved using the share-to functionality of the device's operating system. No data is retained afterwards.

Being a PWA, the mobilescan app is readily available.

## Workflow outline

Upon visiting the hosting website https://mobilescan.app
the browser prompts to install the progressive web application.

When the app is online and the website carries a newer build, the start page also shows an update button (refresh icon) below the start button; tapping it installs the update and reloads the app. Offline, the button never appears.

The start page shows a "Dokument scannen" button, which enables the camera with a dashed frame in DIN A* format superimposed on the live image (portrait orientation).
The frame shall be about 90% of the total image size, to allow for later rotation/correction.

While aiming, the app looks for a document inside the frame. When one is found with confidence, the dashed frame turns green and traces the outline of the page (its four corners, as the auto-detect in the crop/rotate view finds them), so the user sees before taking the picture that the scan will come out right. Taking the picture then applies the perspective correction on its own: the captured image shows the page upright. When no document is found, the frame stays grey and the picture is taken as before. This detection can be switched off with a toggle button (magic-wand icon) next to the camera button; it is on by default and the choice is kept until the app is closed. The picture is always taken by the user; the app never captures on its own.

Details: `intent/v0.10-live-detect.md`, mockup `intent/mockups/v0.10-01-live-detect.svg`.

A button symbolizing the usual camera button is displayed below the image.

Once pressed, the image is taken and displayed.
The image taken shall be larger than the image displayed: The dashed frame from above defines the visible image, the remaining 10% are not shown here but are available for below image correction options.

Four buttons are available below the image:
"back" to go back to the camera,
"share" to save the result,
"edit" with a submenu of:

"crop/rotate image",
"brightness/contrast",

and "+" to scan another page (see "Several pages" below).

(all buttons carry icons, not labels)

Mockups: `intent/mockups/v0.1-*.svg`, `intent/mockups/v0.5-*.svg`.

### Several pages

A scan can consist of several pages. "+" opens the camera for the next page, which is appended after the last one and becomes the current page. With two or more pages a header above the image shows the position ("2/2") with arrows to move between pages. "back" removes the current page (with a single page it returns to the camera as before). Editing always applies to the current page only. Sharing builds one PDF with all pages in capture order. Pages that are not on screen are held as compressed images so that up to 20 pages fit into a phone's memory.

Details: `intent/v0.5-multi-page.md`.

### Looking closely

Two fingers on the image magnify it (pinch zoom), so the user can check whether text is legible or a frame edge sits on the paper edge without sharing first. Zoomed in, one finger pans the image; swiping between pages works only in the fitted view. A double tap toggles between the fitted view and a threefold magnification at the tapped point. The zoom is limited to the detail the capture holds. Only the image zooms; the buttons, the page header and the slider stay in place. The zoom is view state only: it is never saved or shared and resets whenever the view is left, the page is switched or an edit is applied. The same works in the crop/rotate and brightness/contrast views. In crop mode the handles keep priority: a finger on a handle drags it, a finger clear of the handles pans; in rotate mode one finger always rotates, so panning there needs two fingers.

Details: `intent/v0.9-zoom.md`, mockup `intent/mockups/v0.9-01-zoom.svg`.

## Image correction

### Cropping and rotating

In crop mode, a dashed frame is displayed on the image, which again is displayed in 100%, with the dashed frame in the location defined during image capture.
Below the frame are five buttons: a back button on the left, a toggle/segmented control button with a crop/shear icon and a rotate icon, a "rotate 90 degrees right" button, an auto-detect button (magic wand), and a confirm (checkmark) button on the right.

In crop mode:
The user can now touch-drag the frame, the four edges (independently) and the four corners (affecting two edges at the same time).

The image stays constant, but the frame is moved.

In rotate mode:
The user can now rotate the frame by dragging around the frame boundary. This is for fine skew correction of about ±15 degrees.

The "rotate 90 degrees right" button turns the image in 90 degree steps (clockwise) and is available in both crop and rotate mode. Four taps return to the original orientation.

Switching back to crop mode allows cropping again. Note that the frame is likely to be rotated, so cropping must be independent of frame orientation (i.e. always based on the frame, not on the device).

Pressing the checkmark modifies the image if rotations were selected and returns to the previous main image view.
During rotation, the required fill-ins in the corners are provided in white.

Cropping results simply store the updated frame size, i.e. cropping does not modify the image itself.

While a drag is in progress, magnified previews (loupes) of the affected frame corners appear in the centre of the image: one for a corner, two for an edge, four for moving the frame or rotating it. They show whether the frame edge sits on the paper edge without lifting the finger and disappear on release.

Crop mode also corrects perspective (shear) for a page photographed from an angle: each of the four corner handles pulls that corner onto the corresponding paper corner on its own, so the frame becomes a quadrilateral, while the edge handles keep cropping. The frame body itself is not draggable. The mode carries the shear icon and is the default. Confirm warps the image so the quadrilateral becomes an upright rectangle (perspective correction), with white fill where no image lands; the margins around the page are kept, like with rotation.

The auto-detect button looks for the paper edges close to the frame (from a little outside to a fifth of the way inward) and moves the frame onto them: rectangle, rotation and, for a page photographed at an angle, displaced corners. Edges it cannot find keep their current position; if it finds none, a brief warning is shown and the frame stays. The result is a pending edit like any drag: confirm bakes it, back discards it.

Details: `intent/v0.2-crop-rotate.md`, `intent/v0.6-loupes.md`, `intent/v0.7-shear.md`, `intent/v0.8-auto-detect.md`, mockups `intent/mockups/v0.2-*.svg`, `intent/mockups/v0.6-*.svg`, `intent/mockups/v0.7-*.svg`, `intent/mockups/v0.8-01-*.svg`.

### Brightness/contrast
Similar buttons to crop/rotate: [back] [brightness|contrast|temperature] [b/w] [auto] [ok]
One slider below the image adjusts the value selected by the toggle: brightness, contrast, or colour temperature (cool .. warm), the latter for neutralising a colour cast that contrast edits bring out on white paper.
The b/w button toggles a conversion to grayscale.
Adjusting changes the displayed image but not yet the image itself (optimize for touch reaction speed).
Pressing ok then applies the changes to the image.
The auto button (magic wand) switches to black-and-white, measures the paper background and the print, and sets brightness and contrast so the page becomes full black on white; the slider then shows the value of the selected toggle and the result can be corrected before ok. The contrast range reaches 4.0 for this, with the neutral tick at the slider's centre.

Details: `intent/v0.3-brightness-contrast.md`, `intent/v0.8-auto-detect.md`, mockups `intent/mockups/v0.3-*.svg`, `intent/mockups/v0.8-02-*.svg`.

## Sharing

Pressing share opens a sheet with a three-level compression control (icons for small, medium, large file) and a confirm button.
Saving the image uses the Browser+OS share-to functions, where the user can select an app as target.
During sharing, each page's image is compressed and embedded best-fit in the PDF: a fixed DIN A4 page per scanned page, whose orientation follows the image, with the image scaled to fit the page. If the cropped image does not have the A4 aspect ratio, borders remain on one axis.

After successful sharing, the image is not retained in the app any longer and the app returns to the start page. If the share sheet is cancelled, the captured image stays available.

## Deployment

MobileScan is hosted on uberspace at https://mobilescan.app

The artifacts are just the static web page, delivered by apache.
No server component exists.

Deployment happens via a script that scps the artifacts to the host. Host and target path are read from a git-ignored `.env` file (`DEPLOY_HOST`, `DEPLOY_PATH`).
