# MobileScan

MobileScan is a progressive web app that allows users to scan paper documents on mobile devices (Android + iPhone) and save them as PDFs with minimal image processing.

## Project state

v0.3 is implemented (capture + share, crop/rotate, brightness/contrast). Run `npm install`, then `npm run dev` for a local HTTPS
dev server reachable from a phone on the LAN, or `npm run build` / `npm run deploy`; see
`CLAUDE.md` for the full command list. The spec below is the authoritative UX description.
Open questions in it have been resolved and the resolutions are recorded in `intent/`:

- `intent/2026-09-22-spec-assessment-and-decisions.md`: gap assessment and decisions (tech stack, PDF page, compression UI, rotation, share outcome, deployment).
- `intent/README.md`: the version roadmap.
- `intent/v0.1-mvp.md`, `intent/v0.2-crop-rotate.md`, `intent/v0.3-brightness-contrast.md`, `intent/v0.4-ui-polish.md`: one definition per version with scope, behaviour, data model and acceptance criteria.
- `intent/icons/`: the icon set and app icon. `intent/mockups/`: phone-screen mockups, generated by `intent/mockups/generate.py`.

Tech stack: TypeScript + Vite, no UI framework, Vitest for the geometry and image maths, pdf-lib for the PDF.

## Raison d'etre

MobileScan is a small utility app that does not send data anywhere except for the save / share-to location selected by the user. In particular, all processing happens locally in the device's browser.
Its sole purpose is to scan a paper document, allow for simple cropping as well as brightness + contrast correction, and embed the resulting image in a PDF file with selectable compression level.
The PDF is then saved using the share-to functionality of the device's operating system. No data is retained afterwards.

Being a PWA, the mobilescan app is readily available.

## Workflow outline

Upon visiting the hosting website https://mobilescan.app
the browser prompts to install the progressive web application.

The start page shows a "Dokument scannen" button, which enables the camera with a dashed frame in DIN A* format superimposed on the live image (portrait orientation).
The frame shall be about 90% of the total image size, to allow for later rotation/correction.

A button symbolizing the usual camera button is displayed below the image.

Once pressed, the image is taken and displayed.
The image taken shall be larger than the image displayed: The dashed frame from above defines the visible image, the remaining 10% are not shown here but are available for below image correction options.

Three buttons are available below the image:
"back" to go back to the camera,
"share" to save the result,
"edit" with a submenu of:

"crop/rotate image",
"brightness/contrast".

(all buttons carry icons, not labels)

Mockups: `intent/mockups/v0.1-*.svg`.

## Image correction

### Cropping and rotating

In crop mode, a dashed frame is displayed on the image, which again is displayed in 100%, with the dashed frame in the location defined during image capture.
Below the frame are four buttons: a back button on the left, a toggle/segmented control button with a crop icon and a rotate icon, a "rotate 90 degrees right" button, and a confirm (checkmark) button on the right.

In crop mode:
The user can now touch-drag the frame, the four edges (independently) and the four corners (affecting two edges at the same time).

The image stays constant, but the frame is moved.

In rotate mode:
The user can now rotate the frame by dragging around the frame boundary. This is for fine skew correction of about ±15 degrees.

The "rotate 90 degrees right" button turns the image in 90 degree steps (clockwise) and is available in both crop and rotate mode. Four taps return to the original orientation.

Switching back to crop mode allows cropping again. Note that the frame is likely to be rotated, so cropping must be independent of frame orientation (i.e. always based on the frame, not on the device).

Pressing the checkmark modifies the image if rotations were selected and returns to the previous main image view.
During rotation, the required fill-ins in the corners are provided in white.

Cropping results simply store the updated frame size, i.e. cropping does not modify the image itself.

Details: `intent/v0.2-crop-rotate.md`, mockups `intent/mockups/v0.2-*.svg`.

### Brightness/contrast
Similar buttons to crop/rotate: [back] [brightness|contrast] [ok]
One slider below the image adjusts the value selected by the toggle.
Adjusting changes the displayed image but not yet the image itself (optimize for touch reaction speed).
Pressing ok then applies the changes to the image.

Details: `intent/v0.3-brightness-contrast.md`, mockups `intent/mockups/v0.3-*.svg`.

## Sharing

Pressing share opens a sheet with a three-level compression control (icons for small, medium, large file) and a confirm button.
Saving the image uses the Browser+OS share-to functions, where the user can select an app as target.
During sharing, the image is compressed and embedded best-fit in a PDF: a fixed DIN A4 page whose orientation follows the image, with the image scaled to fit the page. If the cropped image does not have the A4 aspect ratio, borders remain on one axis.

After successful sharing, the image is not retained in the app any longer and the app returns to the start page. If the share sheet is cancelled, the captured image stays available.

## Deployment

MobileScan is hosted on uberspace at https://mobilescan.app

The artifacts are just the static web page, delivered by apache.
No server component exists.

Deployment happens via a script that scps the artifacts to the host. Host and target path are read from a git-ignored `.env` file (`DEPLOY_HOST`, `DEPLOY_PATH`).
